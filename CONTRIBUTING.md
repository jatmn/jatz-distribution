# Contributing

Jat'z Distribution is a Factorio 2.1 mod in active development, released on the [Factorio Mod Portal](https://mods.factorio.com/mod/jatz-distribution). Report ordinary bugs in [Issues](https://github.com/jatmn/jatz-distribution/issues), including the mod version (or commit, for a build from `main`), Factorio version, other enabled mods, reproduction steps, and relevant redacted logs. Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md).

Read [AGENTS.md](AGENTS.md) before changing code or artwork, the notes in [docs/design/](docs/design/) for the part you change, and [docs/testing.md](docs/testing.md) for the tests. Propose larger gameplay or artwork changes in an issue first. Keep pull requests focused, explain the behavior changed, and include the checks you ran. The owner reviews and merges changes; outside contributors' workflow runs require approval.

**UPS is part of every pull request that can change what the game does each tick:** `control.lua`, `scripts/`, `data-final-fixes.lua`, prototypes the game simulates (entities, units, tiles, collision layers), what runtime settings do, and the benchmark itself. Recipes, technology costs, locale, icons, artwork, documentation and tooling don't need it: write "Not applicable" and why. [docs/benchmark.md](docs/benchmark.md#pull-requests) has the full list. For the rest, run `python3 tools/benchmark_ups.py --factorio <factorio> --compare origin/main` on your machine and paste the table it prints into the pull request template's "UPS before and after" section. It benchmarks your branch and `main` on the same machine, so hardware differences cancel out; [docs/benchmark.md](docs/benchmark.md) explains the numbers and holds the baseline to judge them against. CI's **UPS benchmark** check comments an engine-free comparison of the mod's script cost on the pull request (for a pull request from a fork, only in the check's summary), but it doesn't replace the in-game run.

Use the pinned tool versions in `.github/workflows/area.yml`. For repository-tool changes, run the relevant `tools/test_*.py`, Ruff, and actionlint. Lua changes need Lua 5.2 syntax checks, Luacheck, and StyLua; mod behavior changes also need `tools/test_mod_setup.py` and the Factorio checks in [docs/testing.md](docs/testing.md). A passing `CI result` does not replace review of changes to workflows or their scripts.

Install hk 2.13.0 and the pinned static tools on your `PATH`, then run `hk install` in this clone. The pre-commit hook formats staged Lua with StyLua and runs the applicable static checks. The pre-push hook checks the whole working tree with Lua 5.2, Luacheck, StyLua, Python, Ruff and actionlint. Run `hk check --all --no-fail-fast` to run those checks directly. The workflow runs the package, tests and benchmarks against the pushed revision.

Dependabot proposes weekly updates for Python development packages and GitHub Actions. Updates still need review and CI; they are not merged automatically. A Pullfrog action update must also update `PULLFROG_VERSION` in `tools/pullfrog_command.py` and pass its authorization tests. Preserve commit-SHA action pins, checksum-verified tool downloads, and the owner-only Pullfrog trigger.

Do not commit credentials, local environment files, machine paths, game binaries, saves, or private logs. Disable Blender's filename/hostname metadata when producing preview renders. Preserve the artwork sources and pixel content when cleaning metadata. New source files and third-party material must follow the licensing rules in AGENTS.md and NOTICE.

Use Conventional Commit PR titles such as `fix: preserve freighter cargo` or `ci: update release checks`; Release Please uses them for GitHub release notes. For a player-facing change, add a new file `changelog/unreleased/<short-name>.txt` with a Factorio category such as `  Bugfixes:` and entries beginning `    - `. Do not edit `changelog.txt`; the release PR assembles those files into it. Leave version numbers to the release PR. See [the release guide](docs/releases.md) for packaging, credentials and publication.
